## 2. 已确认的静态代码风险

### A. 风洞滑块与概率输出可能脱节

`windtunnel.html` 的 `render()` 使用四个变量计算年度增长轨道；转换为共享模型路径后，代码修改 `paths[0]`、`paths[1]`、`paths[3]`，没有把房地产滑块 `s3` 映射到模型概率计算。因此房地产变量可能改变增长轨道，但不改变该模型输出的达标概率。

修复原则：先明确每个变量的模型语义与映射依据，再修正计算链路；不得为了让数字变化而随意编造参数映射，也不得擅自改变共享算法。

### B. 报告路径系数图存在标签与数值错配风险

`report.html` 的路径系数图固定展示六个标签，但共享模型 `HT.run()` 的 `coefs` 对应五条路径；其中还包含硬编码数值，并按索引取模型系数。模型路径顺序为：
- 0：双引擎·电子信息+新能源
- 1：工业底盘自然延续
- 2：三产/文旅破局
- 3：融深融莞通道
- 4：一产·特色农业

修复原则：标签和数值必须由同一份路径元数据生成。没有对应模型系数的因素单独展示并标明其分析口径，不混入共享模型系数序列。

### C. 多套关系图的数据与交互边界需要明确

- `holo-home-v10.html`：关系世界 V10；证据模式读取 `data/relationship-evidence-v1.json`、`data/relationship-sources-v1.json`、`data/relationship-changes-v1.json`。
- `holo-home-v9.html`：旧版关系观测站/概念版。
- `network.html`：产业网络 X 光机，包含自己的节点定义与冲击交互。

当前静态检查不足以证明三者使用完全相同的节点、关系和更新规则。应保留页面，先核实差异与职责；本次不改动任何全息页面。

### D. 页面导航不完全一致

主页面大多共享主导航，但 `network.html` 的导航缺少部分主线入口。需要统一正式页面导航和“下一步”行动，同时保留返回与直接跳转能力。

### E. 测试清单需要对齐正式页面目录

`tests/verify_all.js` 已有语法、模型口径、数据、证据与 UI 隔离检查，但其页面清单包含历史/实验入口。应把正式页面、实验页面、历史页面、全息页面分类登记，并确认各自应有的测试覆盖。

## 3. 页面级 UI 设计原则

- 每页只突出一个主要任务；避免所有内容同时争抢注意力。
- 图表必须回答具体问题，交互结果必须解释“改了什么、为什么变化”。
- 现实事实、推断、模型假设、压力情景分开标识。
- 页面统一导航、排版、间距、卡片、图表容器、按钮、响应式和动效规则；各页仍保留自己的视觉层级。
- 不改模型核心算法、模型基准参数和每日数据抓取流程。
- 全息页面不得加载或继承本次非全息 UI 修改。

## 4. 执行顺序与验收

1. 补齐正式页面/历史页面/实验页面目录与导航映射。
2. 修正可确认的图表标签与展示问题；先为风洞变量映射写清规则再修改。
3. 统一所有非全息页面 UI，覆盖正式入口和确认仍在使用的辅助入口。
4. 执行语法、链接、资源、模型基准、交互、桌面/手机和全息隔离回归检查。
5. 报告修改文件、测试结果与未解决事项；通过验收后再决定合并或发布。
