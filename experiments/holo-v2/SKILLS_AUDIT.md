# SKILLS_AUDIT · 博罗 V2 全息数据宇宙

> 开发执行 Agent 在 M1 开工前的能力盘点：用了哪些 Skill、各自承担什么、缺什么、怎么补。
> 原则：**Skills 服务于项目，不决定项目架构。** 不安装来源不明的 Skill，不授权非必要账号。

## 一、实际调用的 Skills 与工具

| 能力 | 承担者 | 在 M1 中的实际用途 |
|---|---|---|
| 视觉概念生成 | Skill `doubao-creative-design`（`image_gen` / `image_edit`） | 产出五屏全息概念定稿（交织态 / 进入态 / 重组态 / 手机竖屏态 / 信息层 UI），用于锁定视觉语言与交互方向；**不作为最终界面截图** |
| 数据管线参考 | Skill `boluo-intel`（博罗）、`huicheng-intel`（惠城） | 提供 hot.json / life.json 的采集—估算—校验—上线流程参考，作为 M2 真实数据接入的既有管线；M1 未改动这些文件 |
| 数据核查参考 | Skill `huicheng-data-audit` | 提供"官方指标 / 重大项目 / 政策"的核查与证据分级方法，复用到 A/B/C/D 证据体系 |
| 代码读写 | 基础工具 `Read` / `Write` / `Edit` / `Glob` / `Grep` | 全部源码、数据、文档的编写与修改 |
| 命令执行 | `Bash`（node / python3 / git） | 本地预览、node 数值验证、原版质量门、git 隔离 |
| 浏览器自动化 | 预装 **Playwright + Chromium（SwiftShader 软渲染）** | 桌面 1440×900、手机 390×844 双端真实加载、真实点击/触控/搜索、截图、控制台错误采集 |
| 自动化测试 | Node 内置 `node:test` + `node:assert` | 数据层与计算层 23 项断言（见下） |

## 二、没有现成 Skill、由本工程自建的部分

| 能力 | 为什么没有用 Skill | 自建方式 |
|---|---|---|
| 3D 全息渲染 | 无专用 WebGL/three.js Skill；产物是高度定制的节点-关系星群，通用可视化 Skill 无法满足证据等级语义 | 原生 ES Modules + 本地 **three.js r128 UMD**，手写渲染层（`src/scene/`） |
| 力导向布局 | 通用图库（d3-force）难以保证"跨群边不参与布局、同主体位置稳定"的硬约束 | 手写确定性两阶段社区保持布局（`src/core/layout.js`，固定种子） |
| 不确定性 / 推断引擎 | 无对应 Skill；需严格区分观测/推断/假设 | 纯函数 `src/core/uncertainty.js`（最大乘积路径 + 证据地板，确定性、可复算） |
| 交互与状态机 | 无对应 Skill | 手写发布订阅 store + 射线拾取 + 触控手势（`src/state/`、`src/ui/`） |
| 移动端 2D 降级 | 无对应 Skill | `src/ui/fallback.js`，WebGL 不可用时 canvas 俯视关系图，仍可点选/搜索 |
| 双端回归截图 | 无对应 Skill | `scripts/screenshot.mjs`（Playwright，双端 12 张 + 控制台错误采集） |

## 三、能力缺口与补足方案

| 缺口 | 影响里程碑 | 补足方案（不新增不可信 Skill） |
|---|---|---|
| 真实镇际人流 / 通勤 / 物流矩阵 | M2 / M3 | 走 `boluo-intel` 式公开情报流程：道路断面、就业人口、产业园分布、匿名聚合通勤等多源约束；拿不到就显示"未知 / 假设"，绝不编造 |
| 真实行政区边界 / 地形坐标 | 不影响 M1（本方向已放弃真实地图外形） | 若未来需要地理底图，使用可靠行政区矢量数据单独建层；M1 是关系空间，不需要 |
| 自动化视觉回归（像素 diff） | M2 | 可在 screenshot 脚本基础上增加基线图比对；M1 用"脚本截图 + 人工目检 + 控制台错误"兜底 |
| 前端工程化（TS / 打包 / 单测 DOM） | 复杂度上升后 | 当前刻意无构建链；M2/M3 模块变多可平滑迁移到 Vite + TypeScript（见 ARCHITECTURE.md） |

## 四、纪律确认

- 没有安装任何第三方 Skill，没有授权任何额外账号，没有在前端打包任何密钥。
- 远程仓库地址中内嵌的 push 凭据仅留在本地 git remote，未写入任何前端文件或文档。
- 所有"对外可见"的能力都来自本地源码 + 公开数据，无黑盒依赖。
