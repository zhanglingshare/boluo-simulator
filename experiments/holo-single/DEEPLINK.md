# 看见博罗 · 三版本深链接协议（Deep Link）

> 目的：让三个产品围绕**同一个问题**自动接力，而不是让用户在产品之间做选择题。
> 用户在全息版（EXPLORE）发现结构线索 → 带着问题进入风洞2.0（LEARN）做取舍 → 带着判断到原版（ANALYZE）核验证据。
> 完整接力是能力，不是强制流程；任何一站都可单独进入。

## 一、三个产品与路径

| 产品 | 普通用户命名 | 回答的问题 | 文件 |
|---|---|---|---|
| EXPLORE 全息版 | 看见博罗·全息探索 | 博罗有哪些不容易被看见的联系？ | `experiments/holo-single/index.html` |
| LEARN 风洞2.0 | 博罗决策沙盘 | 面对复杂局面，怎样形成判断？ | `v2/index.html` |
| ANALYZE 原版 | 博罗产业风洞 | 我的判断有哪些事实支持？稳健吗？ | `network.html`（及 report/future/windtunnel） |

## 二、统一 URL 参数（上下文协议）

跨产品跳转一律用 **query 参数**（`?`，不用 hash，避免与目标页既有 hash 冲突）：

| 参数 | 含义 | 取值 |
|---|---|---|
| `entity` | 统一实体 id（节点） | 27 个节点 id，全息版与原版 network.html 完全一致 |
| `scene` | 风洞2.0 情景 id | `base`/`upside`/`investment`/`property`/`combined` |
| `topic` | 议题 id（把三者串成同一问题） | 见议题映射表 |
| `from` | 来源产品，用于"返回"提示 | `holo`/`learn`/`analyze` |
| `dv` | 数据版本标识 | 快照/模型版本，保证"看到的是同一批数据" |

规则：
- **目标页收到无法识别或无法精确定位的参数，必须退回普通入口**，不伪装定位、不编造对应内容。
- 参数只负责"定位/展开"，不改变任何事实数据；模型参数不被 URL 改写。
- 科学边界：全息版的结构联系 ≠ 已证实导致宏观变化；进入风洞2.0 时说明引入了新假设，不做无缝因果包装。

## 三、议题映射表（topicId）

一个议题 = 同一个问题在三个产品里的三个锚点。

### topic: `inv-industry`（投资下行，工业为何仍增长）

- 核心问题：工业投资大幅下行，规上工业增加值为何仍在增长？
- 全息版锚点：`entity=xwd`（园洲·欣旺达/锂威），从产业网络看结构。
- 风洞2.0锚点：`scene=investment`（投资持续低迷情景），做"项目投产延期如何调整重心"的取舍。
- 原版锚点：`network.html?entity=xwd`，查看该节点的关系、证据与中心度。
- 接力：
  1. 全息：选中 xwd →「查看这一主体的证据 → 原版」
  2. 全息：M3/节点 →「想知道这些联系怎样影响未来 → 风洞2.0·投资情景」
  3. 风洞2.0：最后一步可「回到原版核验证据」

> 新增议题时，必须在三个产品里都找到**真实存在**的锚点，才能进入映射表；找不到的，深链接退回普通入口。

## 四、各产品需要支持的参数（最小增量，向后兼容）

- `network.html`：新增读取 `?entity=xxx`，加载后程序化选中该节点（高亮邻居 + 详情）；无参数时行为不变。
- `v2/index.html`：新增读取 `?scene=xxx`（+ 可选 `?topic=`），预设对应情景并显示"来自全息版的问题"提示；用户仍走完整七幕。
- `experiments/holo-single/index.html`：内联深链接构造器，在节点/边浮卡与 M3 中就近提供跳转入口。

## 五、数据版本

- 深链接携带 `dv`，目标页若数据版本不一致，提示"数据已更新，结果可能略有差异"，但不阻断查看。
- 事实、模型、用户假设分层：事件/生活按采集更新，指标按统计周期，**模型参数经审核校准才发版**，用户假设私有。
