# 博罗 V2 · M3 · 全息情景推演与双世界探索

在 M2 的 `experiments/holo-single/` 之上叠加的独立模块（`m3/` 子目录），不触动 M2 原引擎、原版首页、旧版 `/v2/` 或 `model.js`。

M3 让用户能对**未知变量**（园洲+石湾—东莞跨界通勤联系强度）选择低/中/高/自定义情景，系统调用真实计算函数重算网络，再以两座并排全息世界呈现结构差异，并给出稳健结论与关键未知。

## 运行

仓库根目录：`python3 -m http.server 8765`，访问
`http://localhost:8765/experiments/holo-single/index.html`。

进入 M3 的三个入口：
1. 桌面端顶栏右侧「◈ 双世界推演」；
2. M2「未知实验」模式面板里的「◈ 打开双世界对撞」（全端，最贴近“发现未知联系→进入推演”的路径）；
3. 手机端左下角浮动按钮「◈ 双世界」（顶栏容器在 ≤720px 被隐藏，故单独提供）。

## 已实现能力（M3-A / B / C / D）

- **M3-A 区间实验**：世界 A/B 各自可选 低/中/高（4,500 / 10,000 / 17,000 人次/工作日，来自 atlas 的 B 级区间）或拖动自定义滑块；每次改变都调用 `simulate()` 真实重算关系权重、可达集合与局部位置，节点/连线/可达数即时变化，相同输入结果一致。
- **M3-B 双世界对撞**：两座 Canvas 共享同一节点身份、基准布局、旋转/缩放与选中；差异高亮——共同连通（青）、仅本世界连通（暖橙描边环）、另一世界连通（灰色空心环）、随情景变化的 B 级关系（紫/橙，越强越亮）。
- **M3-C 敏感性与稳健发现**：`sensitivity()` 在 u∈[0,1] 扫描 21 个点，区分**稳健可达 / 条件性 / 永不连通**，给出每个条件性主体的可达阈值与所在区间（低→中、中→高），低/中/高可达数条带，以及“下一步最有价值的公开数据”（来自 atlas 的 `toTighten`）。
- **M3-D 保存与复算**：本地保存/恢复、导出/导入 JSON（含两情景输入、选中、视角、数据签名、模型版本）；版本或数据签名不匹配时禁止恢复，防止把旧结论套到新数据上。桌面与手机双端均已用 Playwright 走通。

## 情报复核（B 级区间的依据，见 `data/atlas.json`）

通勤流场（`flow_yuanzhou_shiwan_dongguan_commute`）采用**双方法交叉验证**：
- 方法一（自下而上·结构系数法）：就业基数约 24 万 × 跨界通勤系数 2%/4%/7% ≈ 4,500 / 10,000 / 17,000 人次/工作日（双向合计）。
- 方法二（自上而下·总量倒推，仅作合理性校验）：中移动 2022 年 9–11 月手机信令研究给出莞惠跨市日均出行约 40 万人次（全目的、双向），按份额与通勤占比倒推园洲+石湾段约 1.4 万–7.3 万，带宽大、仅作天花板校验。
- 两法重叠区约 1 万–1.7 万，中/高情景获总量校验支持；低情景 4,500 低于倒推下界，属保守弱通勤假设。区间维持 B 级不改值，共 9 个来源（含跨市公交、十四五纲要、副中心人口、手机信令论文等）。

## 科学边界（硬约束）

- 源码：`engine.mjs` 为纯函数（结构引擎 + 区间映射 + 敏感性 + 保存校验），`ui.mjs` 为浏览器 UI，`ui.css` 为响应式样式。
- **双轨设计**：`simulate()` 只输出无量纲结构结果（权重/可达/位置），绝不含真实人数、GDP、概率；真实人次由独立函数 `uToFlow()` 作为情景标签呈现，**不反向驱动结构权重**。u 与人次是可解释的单调情景对应，不是因果换算。
- 自定义位置的人次是 C 级插值示意（±12% 带宽，**不是统计置信区间**）；超出 B 级区间时钳到边界，不向外外推。
- A 级关系权重恒为 1、不可调；只有 e3、e12、e13、e14 四条与东莞产业联动相关的 B 级关系随 u 变化（B 焦点 `w=0.10+0.85u`，其余 B 固定 0.28，C 固定 0.07）；可达阈值 0.48 是结构模型规则，无交通/统计含义。
- 高情景新增可达的主体（如深圳、正威、欣旺达）均经真实 A/B 边链 BFS 得到，例如 东莞→(A)石湾模具→(B)欣旺达→(A)深圳；focal B 边是“桥梁”，连带激活既有 A 级连接。
- 不输出 GDP、就业、2030 目标达成概率；用户选择的是探索假设，不是在修改官方统计。
