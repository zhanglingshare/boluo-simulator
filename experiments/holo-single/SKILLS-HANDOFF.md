# 博罗关系世界｜双情报源接入与发布约束

## 职责
- ChatGPT 与豆包 Skills 均可发现、整理、核验公开信息；系统不按采集工具决定证据可靠性。
- 前端只消费经过检查与审核的正式快照，不直接消费状态为 `candidate` 的交接包，也不因某条新闻自动改变已存在的产业关系。
- 当前关系世界使用仓库根 `data/industry-graph.json`（27主体/30关系）、`hot.json`、`life.json`，及本目录 `data/atlas.json`（16镇街）。
- C004 单独读取 `data/relationship-changes-v1.json`、`data/relationship-evidence-v1.json`、`data/relationship-sources-v1.json`。项目的 `node_status=pending` 与 C 级待验证边不可提升为投产或真实供货。
- 未证实主体不应自动加入 27 主体的生产网络；需要核验建设、达产及稳定供应关系的证据后，再决定是否升级。

## 新数据进来之前
1. 记录来源网址、来源发布者、事件发生时间、报道发布时间、核验时间、对象ID和事实/推断/情景类型。
2. 保持主体ID稳定。正式产业关系由端点 `source/target` 与关系类型生成稳定结构ID `rel:...:...`（保持旧版30条关系的身份）。
3. 禁止只重排数组就让模型推演对象变化；新增可能同主体对、同类别的第二条关系时，必须升级ID协议，禁止覆盖既有关系。
4. 校验所有边的两端存在、实体和边ID无重复、事件/来源引用完整；出现歧义时拒绝自动发版并保留上一份合格快照。
5. 完成模型复现和场景检查后才发布，前端不直接把估算映射成真实交易或确定的经济预测。

## 当前产品限制
- 现有M3仍然在公开JavaScript中提供可复现的结构实验计算；界面不强调内部公式，但GitHub Pages不能从技术上隐藏公开源码。真正私有的模型需迁移到受控计算服务，或发布预计算情景快照。
- 两世界的“4→9可达节点”是模型内结构结果，不是真实可通勤人数、就业、GDP，也不是发生概率。
- `我的观察`保存在当前浏览器本机，只用于此页回访；尚不与`report.html`自动同步。
- 页面可通过 `?entity=<id>`、`?town=<name>`、`?cluster=<group>`、`?change=C004` 继续探索；已有 `#change=C004` 保持兼容。

## 验收
执行现有的`node --test experiments/holo-single/tests`、`node tests/verify_all.js`，并在桌面和手机浏览器检查全景、主体、两跳、镇街、C004、M3与弹窗。若无法完成浏览器实测，不应声称实测通过。
