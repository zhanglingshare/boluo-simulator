# 博罗统一研究契约 V1（独立增量，不覆盖旧版）

## 交付文件
- `variables.v1.json`: 24个变量的变量类型、单位、统计口径、频率、证据默认级别与源码映射。**不是观测数据。**
- `models.v1.json`: 8个已有模型的代码入口、输出量纲、限制和跨模型不可比规则。所有模型当前登记为 `source_verified_adapter_pending`，**未声明适配成功**。
- `scenario.example.v1.json`: 合成条件的示例情景，同期范围与随机种子。
- `contract-v1.js`: Node/浏览器通用的纯校验函数、模型查询和结果封装；不调用、重写任何经济模型。
- `tests/boluo-contract-v1.cjs`: 场景格式、证据等级、单位不匹配、模型不可比、版本差异等测试。

## 核心约束
1. GDP及三次产业增加值是期间流量，不能与企业营业收入、项目投资额、总产出直接相加。
2. 企业 V13 的36项是**合成战术属性**，不是已测得的企业观测值。球探24项是独立原型，暂不可自动等同。
3. 2030 GDP、2032产业结构、28季度经营能力分、网络压力指数各自独立；单位相同也不充分证明经济意义可比。
4. 原注册表 `data-manifest.json` 仍保留，不擅自重定向失效文件；修复须回查真实底座。
5. 真实数据上传并不自动标记为已核实，需审核人、来源及统计口径。
6. 情景 `changes` 目前是对参数的协议性描述，不意味着任一已登记模型真正消费这些值。
7. `compareOutputs` 只做保守的元信息检查，不验证统计识别、模型等价或因果效应。

## 下一阶段接口适配顺序
1. 优先使用 `lab-2032/core.js` 的 `BoluoCore` 数据快照、质量检查与导入输出，不复制生成830主体和问卷的逻辑。
2. 为 `lab-2032/engine.js` `BoluoEngine.simulate` 建**只读适配器**；保留原模型方法与现有UI；锁定基准快照后验证前后结果完全一致。
3. 为内部 `career-montecarlo-v12.js` 建局部只读导出适配器，不能脱离 `careerTick` 的全局状态与加载顺序直接复刻。
4. 调度层只派发**可匹配输入的模型**，绝不为缺失数据填入伪造的现实值。
5. 在部署前对同种子同模型重复、不同单位阻断、跨快照不可比、旧版回归进行自动验收。
